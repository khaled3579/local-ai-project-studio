# 4.16.2 — requirement review, repetition and acceptance evidence

Requirement review errors now return the exact failing requirement, bounded original text, its length, current revision and conservative repair guidance. A failed batch saves no rows. Exact literal fragments (with explicit occurrence when ambiguous) normalize into the existing numeric-span ledger, preserving IDs and coverage rules. Pending review guidance is bounded without deleting requirements or old plans.

Repeated validate_project calls can reuse an actual passing execution only within the current job, with matching source fingerprint, validator, saved report identity, immutable baseline, quality/performance policies and recorded execution context. Failed or changed evidence is never cached. An explicit force=true needs a concrete reason for external inputs. Final validation uses the same check. The execution context covers environment variables and local Python environment metadata; arbitrary external services, clocks and dependency internals are not fully modeled. Changed external inputs require explicit revalidation. A validation that creates an environment is deliberately not immediately cached.

Explicit supported targeted-patch constraints require a host-recorded patch to an existing non-test source whose resulting hash matches current bytes. The scope is that actual patch, not a claim that every historical edit was a patch. Recognized whole-clause comment-preservation constraints require exact original comment tokens in the same file and order; extra comments are permitted. Python tokenization and the bundled TypeScript parser separate real comments from strings, regex literals, templates and JSX text. Changed unsupported source languages fail closed for this receipt. This does not turn arbitrary behavioral requirements into host-only checks; semantic assertion review remains necessary.

## Evidence and limitations

- 190 isolated regression tests passed, including malicious/stale links, atomic failed reviews, Unicode literal splitting, source/report/environment invalidation, resume persistence, actual patch provenance, and comment deletion/reordering/string counterexamples.
- Twenty equivalent validation requests on a prepared synthetic Python project caused one real named-suite execution and nineteen exact receipt reuses. A source change then caused real re-execution and a failing test; that failure was not cached. This measures repeated validation execution, not model-token savings.
- Six exploratory v1 local-model attempts are retained, including a raw success rejected because a price test did not prove comment preservation. Exploratory timings overlapped development and packaging and are not clean performance measurements.
- Six prespecified quiet v2 attempts used frozen sources, identical synthetic tasks, the same loaded model/settings, alternating order, independent behavior/process checks and a review of the exact original fixture assertions. Baseline: 1/3 reviewed acceptances, 43 actual generations, 4 real validations, 3 no-progress repeat candidates. Candidate: 3/3 reviewed acceptances, 32 actual generations, 4 real validations, 5 no-progress repeat candidates. Every failure and budget stop remains in the aggregate.
- After freezing the v2 comparison, the final review tightened unknown-format handling: changed files such as JSONC may not be silently skipped; changed strictly valid JSON has no comment tokens. The final regression counterexample passed, and replaying all four saved JS artifacts produced identical host receipts before and after this boundary fix. It was not a new model benchmark.
- A post-comparison accounting audit found that the old no-progress counter omitted the reused_validation flag: four candidate validation receipts were cache hits, versus one baseline hit. The raw five-versus-three counters remain in the evidence unchanged. A final regression correction explicitly counts validation reuse, retains raw repeat candidates and never records a cached result as new progress. This accounting correction was tested after the frozen benchmark; it is not presented as a new model run or a measured general reduction in repetition.
- This small sample on two tasks does not prove general speed or token savings. Usage on interrupted generations can be incomplete; totals are not extrapolated. Raw acceptance and reviewed acceptance are distinct in the evidence.
- A clean default full installation passed preflight and installed self-tests on frozen v2. The final conservative boundary change was applied to that clean installation with mandatory self-tests, and every one of the final full archive's 8,135 manifest files was reverified against disk. Interrupted source update, rollback preserving newer private drafts, successful re-upgrade and rejection of a tampered archive passed.
- A private legacy copy opened forward and backward with unchanged requirement IDs, conversations, settings and recovery rows. Pending legacy reviews remain pending; no business ambiguity or MFA decision was silently resolved. The trial website is not declared a finished product.

Only reviewed source, synthetic tests and aggregate evidence are published. User projects, raw attempts, conversations, settings, checkpoints, runtime binaries and model weights are excluded.
