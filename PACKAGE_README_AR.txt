حزمة Local AI Project Studio — الإصدار 4.1.1

التشغيل اليومي:
فك ZIP في مجلد مستقل قابل للكتابة ثم شغّل Daily-Projects.cmd. يلزم Python 3.13 x64 مثبت على Windows. الاعتمادات الثمانية مرفقة كعجلات بإصدارات وبصمات SHA-256 مقفلة، وتُثبت دون شبكة داخل .environments. يتضمن runtime محرك llama وNode الرسمي. لا تتضمن الحزمة أوزان النماذج أو Python نفسه أو تعريف NVIDIA وCUDA؛ يفحص Doctor.ps1 متطلبات الجهاز.
لا تنقل بيئة .environments من جهاز آخر. سيُنشئ المشغل بيئة تخص مجلد التثبيت. تبقى إعدادات النموذج والسياق وMTP كما اختارها المستخدم.

الصيانة:
زر «النظام والصيانة» يعرض البيئة وسياسة سجل نشاط المشروع وأحجام بياناته. يُدوّر سجل النشاط عند الحد المحدد ويضغط النسخ القديمة؛ تبقى النسخ الأقدم في cold بلا حذف دائم. سجلات خدمات النظام ومحرك النموذج تُدوّر عند 8MB مع 7 نسخ قريبة، وتُنقل الأقدم إلى cold. تُنشأ سجلات نموذج مستقلة لكل تشغيل.
الأرشفة اليدوية بعد المعاينة تشمل ملفات التصدير ZIP وJSON القديمة فقط، وتُعامل الملفات ذات المعرف نفسه كمجموعة. لا تشمل المحادثات أو المسودات أو المرفقات أو ملفات المشروع أو سجلات الإصدارات أو الاستعادة. الأرشيف المضغوط قابل للاستعادة، ولا يحل محل ملف أحدث. الأرشفة ليست حذفًا دائمًا ولا تضمن تخفيض حجم ZIP المضغوط مسبقًا. راقب المساحة؛ الاحتفاظ المحافظ قد يزيد التخزين مع الوقت.

ترقية موثوقة:
powershell -ExecutionPolicy Bypass -File Update-App.ps1 -Package "C:\Downloads\ProjectStudio.zip" -SHA256 "البصمة المنشورة الموثوقة"
البصمة تحقق سلامة الملف؛ ليست توقيع ناشر رقميًا. استخدم حزمة من مصدر موثوق. يُفحص manifest وكل ملف ومسارات ZIP والاعتمادات ويُجرّب استيراد البرنامج في مجلد منفصل قبل إيقاف الخدمات. الترقية ترفض المهام أو التطبيقات الجارية؛ أوقفها مؤقتًا أولًا. تُحفظ الملفات القديمة وبيانات المشروع المحدد وإعدادات التشغيل تحت .updates/backups. تُنسخ SQLite بواجهة backup المتسقة.
تُحفظ حالة استبدال الملفات في .update-journal.json بعد fsync، ويُرجع المشغل الملفات القديمة عند اكتشاف ترقية انقطعت قبل اكتمالها. إذا فشلت الترقية العادية يُسترجع الكود تلقائيًا. يُعاد تشغيل الخدمات في النهاية، وتُنتظر جاهزية النموذج إن كان جاهزًا قبل الترقية. فشل الجاهزية يعيد الكود السابق ثم يشغّل الخدمات. قفل العملية يتحقق من هوية عملية Windows ووقت إنشائها لتجنب خلط PID مع عملية أحدث.
لتثبيت نسخة أولى: فك الإصدار في مجلد مستقل ثم شغّل Daily-Projects.cmd. أو استخدم app_updates.py install ببيئة مجهزة.

الرجوع:
powershell -ExecutionPolicy Bypass -File Rollback-App.ps1
اختياريًا: -BackupId معرف_النسخة
تُستعاد ملفات البرنامج وهوية الإصدار، وتبقى المحادثات والمسودات التي أُنشئت بعد الترقية. لا تُرجع بيانات المستخدم تلقائيًا. يُرفض الرجوع إذا عُدلت ملفات البرنامج يدويًا بعد الترقية لتجنب الكتابة فوقها. النسخ الاحتياطية لا تُحذف تلقائيًا. لا يدعم هذا الإصدار ترحيلًا غير قابل للعكس؛ إصدار بيانات غير معروف يوقف العملية قبل تغيير البيانات. أغلق الخدمات قبل صيانة الملفات خارج الواجهة.

السجلات:
daily/logs للخدمات والمحرك، و.local-ai/activity.jsonl لكل مشروع. أحداث النشاط تحمل معرف الحدث والمحادثة والمهمة والسلسلة لربط التقارير. بيانات الأعطال قد تتضمن مسارات أو محتوى مشروع؛ راجعها قبل مشاركتها. جودة التحقق v2 وإعدادات النموذج لم تُخفض.

تحديث الفحص النهائي 4.1.0:
نوع الطلب: تلقائي يحوّل التحيات المحددة فقط إلى محادثة، ومحادثة فقط تمنع تعديل الملفات وتشغيل الأوامر والفحوص على الخادم، وتنفيذ على المشروع يبقي فحص التسليم الإلزامي. يُحفظ اختيار النوع لكل مشروع في المتصفح. يجب اختيار محادثة فقط للأسئلة الأخرى التي لا تريد أن تؤدي إلى تعديل الملفات. لا تُضاف رسائل المحادثة الجديدة إلى متطلبات البناء. يتحقق التسليم من مراجع الملفات الفعلية، ويُرفض تشغيل أو تصدير مشروع إذا لم تطابق بصمة المحتوى تقرير الفحص، حتى مع تطابق الحجم والتوقيت.

تصحيح 4.1.1: في الشاشات الصغيرة تدعم مساحة العمل التمرير، ويبقى صندوق الكتابة مثبتًا قرب أسفل المساحة كي يظل زر الإرسال قابلاً للوصول. تم اختبار الضغط عليه بعرض 360 بكسل.

أدوات المساعد 4.4.0:
من زر «أدوات المساعد» يمكن تفعيل مجموعات الأدوات لكل مشروع، وتنفيذها يدويًا، وعرض تقاريرها وصورها. تتاح الأدوات تلقائيًا للنموذج أثناء تنفيذ مهام المشروع. وضع المحادثة فقط يحتفظ بمنع التنفيذ والتعديل. تُحفظ الإعدادات والتقارير تحت .local-ai/tools؛ تبقى خارج ملفات التسليم والكود.
متصفح الفحص Chromium مؤقت ومعزول للصفحات HTML المحلية؛ يضغط العناصر ويدخل القيم ويتحقق من النص ويلتقط الصور ويسجل أخطاء JavaScript والشبكة. لا يستخدم جلسات متصفح المستخدم، ولا يشغّل backend تلقائيًا، ويحظر الموارد الخارجية. المعاينة التشخيصية ليست إثبات نجاح الفحص الشامل. تشغيل الخادم الخلفي أو GUI واختبارات المشروع تبقى عبر أدوات التشغيل والفحص الحالية.
البحث يعرض مقاطع محدودة، ويستخرج تعريفات Python عبر AST وتعريفات JavaScript/TypeScript نصيًا؛ المراجع تطابق لفظي وليست تحليل LSP كاملًا. التشخيص يستخدم Pyright وTypeScript دون استيراد كود Python أو تشغيل أوامر بناء المشروع. قد تحتاج تشخيصات الأنواع إلى تعريفات dependencies الخاصة بالمشروع؛ لا تحل محل الاختبارات المنفذة.
التوثيق يكتشف إصدار Python أو الحزمة المثبتة/المقفلة ويسترجع التوثيق الرسمي للمكتبات القياسية أو README للحزمة بالإصدار المحدد. يرفض تخمين آخر إصدار عند عدم معرفته. يستخدم نسخة مخبأة ليوم واحد؛ بعض الحزم لا توفر README عبر المصدر المدعوم، ويُعلن ذلك بدل اختلاق معلومات.
Git للقراءة فقط: status/diff/history بلا commits أو تعديل staging. نقاط الاسترجاع تستخدم سجل إصدارات البرنامج الحالي. قواعد البيانات المدعومة في هذه المرحلة SQLite داخل المشروع، باتصال mode=ro وquery_only ورفض أوامر الكتابة وATTACH وPRAGMA، وحدود زمنية وحجمية للقراءة. لم تُضف اتصالات PostgreSQL/MySQL أو مفاتيح خدمات خارجية.
يُسجل التنفيذ ضمن سجل الاستعادة الحالي؛ النتائج المكتملة لا يعاد تنفيذها تلقائيًا، والأوامر المنقطعة والملتبسة تتوقف للمراجعة. تعمل المكونات عند الطلب دون تحميل نموذج إضافي؛ متصفح الفحص يعمل مع --disable-gpu لتجنب مزاحمة محرك التوليد. الأدوات ليست صندوق حماية لنظام التشغيل، وكود المشاريع يظل خاضعًا لصلاحيات الحساب كما في الإصدارات السابقة.
الحزمة تتضمن Playwright 1.64.1 وPyright 1.1.414 وTypeScript 5.9.3 وChromium Headless Shell. افحص Doctor.ps1 للتحقق من المكونات وتشغيل المتصفح، أو ارجع للإصدار السابق باستخدام Rollback-App.ps1.

تصحيح 4.4.1: جرى إصلاح تمرير أمر التحقق من إصدار Python في Windows PowerShell 5 حتى تعمل مشغلات CMD الافتراضية، مع بقاء التوافق مع PowerShell 7.
