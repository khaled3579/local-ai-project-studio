# Local AI Project Studio · 4.4.6

مساحة عمل محلية بواجهة عربية لبناء المشاريع البرمجية وإصلاحها باستخدام نماذج GGUF على Windows.

## تنزيل وتشغيل

1. افتح [الإصدارات](https://github.com/khaled3579/local-ai-project-studio/releases/latest) ونزّل **Local-AI-Studio-4.4.6.zip**. ملفا Source code التلقائيان لا يحتويان على مكونات التشغيل الثنائية.
2. ثبّت **Python 3.13 x64** من python.org، مع pip وvenv وTkinter وإتاحته بالأمر `python`.
3. فك الحزمة في مجلد مستقل قابل للكتابة، ثم شغّل `Daily-Projects.cmd`.
4. افتح مساحة المشاريع: http://127.0.0.1:18078/ . إدارة النماذج: http://127.0.0.1:18079/ .
5. من مكتبة النماذج اختر مجلد ملفات GGUF، ثم اختر النموذج واضبط السياق وشغّله. أوزان النماذج لا تُرفق مع البرنامج.
6. أنشئ مشروعًا أو اختر مجلدًا، ثم اختر وضع تنفيذ المشروع واكتب المطلوب. يتولى المساعد استخدام الأدوات والفحص وحفظ الملفات؛ راجع تقرير الفحص قبل التشغيل أو التصدير.

يشمل ZIP محرك llama وNode وChromium وأدوات التحليل وعجلات Python المقفلة. ينشئ المشغّل بيئة Python محلية دون تنزيل اعتمادات Python من الشبكة. يتطلب استرجاع التوثيق والموارد الخارجية اتصالًا بالإنترنت. إعداد مسار النماذج الافتراضي الأصلي قد لا يوجد على جهازك؛ اختر مجلدك من الواجهة عند أول تشغيل.

## المتطلبات

- Windows x64 وPython 3.13 x64، ومجلد تثبيت قابل للكتابة.
- موارد RAM وVRAM تناسب النموذج والسياق؛ اختُبر الإعداد على بطاقتي RTX 3090. لا تعني هذه التجربة ضمان جميع الأجهزة والنماذج.
- تعريف NVIDIA المتوافق مع مكونات CUDA المرفقة عند استخدام تسريع NVIDIA. لا تتضمن الحزمة التعريف أو Python أو أوزان GGUF.
- شغّل `Doctor.ps1` لفحص متطلبات الجهاز والمكونات.

## الإمكانات

- مكتبة نماذج محلية، معلومات GGUF، سياق قابل للكتابة، وتحكم MTP وعدد الخبراء النشطين للنماذج والمحركات الداعمة.
- بث الرد وتقدم المهمة، وإيقاف واستئناف، وحفظ المسودات والمرفقات ومتطلبات المشروع.
- ملفات وصور بالسحب والإفلات، واستيراد مشروع ZIP إلى مجلد مستقل، وتصدير المصادر مع تقرير وتعليمات تشغيل.
- محرر ملفات ومقارنة تغييرات ومعاينة، ووضع مبسط ومتقدم، ولوحة فحص موحدة.
- نسخ احتياطية وإصدارات وتراجع ومحاولات إصلاح تلقائية، واستعادة تقدم السلسلة بعد إعادة التشغيل. الأوامر الملتبسة تتوقف للمراجعة لتجنب تكرار تنفيذها.
- متصفح لفحص صفحات HTML المحلية والأزرار والنماذج وأخطاء JavaScript والشبكة مع لقطات شاشة.
- بحث داخل الكود وتشخيص Python/JavaScript/TypeScript، وتوثيق مرتبط بالإصدار، وقراءة Git وSQLite.
- قراءات الذاكرة والاستخدام والحرارة لبطاقات NVIDIA في الخلفية.

## إصلاحات 4.4.6

- عند فتح مجلد مختلف أو إنشاء مشروع جديد تتوقف معاينة المشروع السابق تلقائيًا، وتنتقل الملفات والمحادثة ومتطلبات العمل إلى المجلد المختار فقط.
- يبدأ المجلد الجديد الفارغ دون مسودات أو مرفقات أو تعليمات من المشروع السابق، مع تنظيف المحرر والمعاينة ومرشح البحث والتقارير القديمة من الواجهة.
- تبقى بيانات كل مشروع محفوظة داخله، وتُستعاد عند العودة إليه دون إعادة تشغيل أوامره تلقائيًا.
- تُرفض طلبات الملفات المؤجلة الخاصة بالمشروع السابق، ولا تعيد تحديثات الواجهة المتأخرة عرض حالته.
- تظهر أخطاء اختيار المجلد داخل نافذة إدارة المشروع. تبقى المهام النشطة محمية من تبديل المجلد أثناء الكتابة.
- بعد الترقية، حدّث التبويبات المفتوحة مرة واحدة لتحميل الواجهة الجديدة.

## إصلاحات 4.4.5 السابقة

- دقة حارس التسليم مع أسماء الملفات المتداخلة، مع رفض الملفات المفقودة والأسماء الملتبسة.
- أهداف تأكيد `auto/text/value/checked/visible/enabled/count/dialog_count`، وقراءة نص الأزرار بصورة صحيحة، وكشف التنبيهات المتكررة.
- حفظ موضع الخطأ الفعلي في السجلات الطويلة، وتحسين متابعة الإصلاح بما يلائم السياق الحقيقي وقالب النموذج.
- تمييز تغير قيم الحقول عن تكرار الخطوات، وتقليل اكتشاف الدوران الزائف.

اجتازت تغييرات 4.4.6 مجموعة من 106 اختبارات للبرنامج، إضافة إلى 19 اختبارًا لمسودات المحادثة والمحرر، واختبار انتقال فعلي بين مجلدات مستقلة أثناء تشغيل المعاينة. سبق أن اجتاز إصدار 4.4.5 دورة مشروع محلي شملت 56 اختبارًا للمشروع و16 تحققًا إضافيًا بالمتصفح. لا تتضمن الملفات المنشورة تقارير الجلسات أو مشاريع الاختبار أو بيانات المستخدم.

## سير عمل يومي

اختر مشروعًا ثم اكتب هدفًا واضحًا ومتطلباته. أرفق لقطة الخطأ أو الملفات عند الحاجة. راقب التقدم وأداة الفحص، وافتح مقارنة الملفات قبل اعتماد تغييرات مهمة. استخدم «محادثة فقط» للأسئلة دون تعديل أو تنفيذ. يمكن تغيير سياق النموذج يدويًا؛ السياق الأكبر يستهلك ذاكرة أكثر، وMTP أو تحكم الخبراء لا يتاحان لجميع النماذج.

متصفح الفحص معزول عن جلسات المتصفح الشخصية ويحظر الموارد الخارجية؛ لذلك لا يثبت فحصه نجاح التكاملات الخارجية أو الدفع أو الحجز الحقيقي. البحث عن المراجع نصي، وتشخيص الأنواع لا يحل محل اختبارات المشروع. قاعدة البيانات المدعومة حاليًا SQLite للقراءة فقط، وأداة Git تعرض الحالة والفروق والسجل دون إنشاء commits.

## الترقية والاسترجاع

أوقف المهام وتطبيقات المشروع الجارية قبل الترقية. استخدم حزمة الإصدار وبصمتها المنشورة:

```powershell
powershell -ExecutionPolicy Bypass -File Update-App.ps1 -Package "C:\Downloads\Local-AI-Studio-4.4.6.zip" -SHA256 "1cde12e92867945cc7760262d7a5cfe700c384dd49f0b3b21fbead0c7ceec11f"
```

للرجوع إلى نسخة محفوظة:

```powershell
powershell -ExecutionPolicy Bypass -File Rollback-App.ps1
```

البصمة للتحقق من سلامة الملف، وليست توقيع ناشر رقميًا. تحتفظ آلية الترقية بنسخ الاسترجاع، وتتحقق من الملفات قبل استبدالها. لا تحذف النسخ الاحتياطية يدويًا قبل التأكد من احتياجك لها.

## البيانات والخصوصية

المستودع لا يتضمن أوزان النماذج أو المحادثات أو المرفقات أو إعدادات الجهاز أو مشاريع المستخدم أو السجلات. ينشئ البرنامج بياناته عند الاستخدام في `daily/` و`.environments/` و`.updates/`، وبيانات المشروع في `.local-ai/` داخل مجلده. لا تشارك هذه المجلدات تلقائيًا؛ قد تحتوي على محتوى ومسارات خاصة. الخدمات ترتبط بـ127.0.0.1 للاستخدام المحلي.

كود المشاريع وأوامرها يعمل بصلاحيات حساب Windows؛ البرنامج ليس صندوق حماية لنظام التشغيل. تحقق من المصادر قبل تشغيل مشاريع مجهولة.
